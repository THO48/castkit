# 测试与验收

## 0. 构建自检

```bash
bash tools/build-receiver.sh      # 期望：BUILD SUCCESSFUL，产出 out/castkit-receiver-debug-app-debug.apk
bash tools/build-sender.sh        # 期望：BUILD SUCCESSFUL，产出 out/castkit-sender-debug-app-debug.apk
```

APK 校验（可选）：

```bash
/opt/android-sdk/build-tools/36.0.0/aapt2 dump badging out/castkit-receiver-debug-app-debug.apk | head -5
```

## 1. 安装

```bash
bash tools/install-apk.sh receiver   # 经 DSHA 桥导出到 Download/DSHA，并在手机上拉起安装器
bash tools/install-apk.sh sender
```

手机上需允许「安装未知来源应用」。装完可在接收端设置里把「随系统启动/后台运行」打开，
并把 App 加入电池优化白名单（HyperOS：设置 → 应用 → 电池 → 无限制）。

### 2.2f 投送会话的收尾

| 编号 | 步骤 | 期望 |
|---|---|---|
| E1 | 投送中在发送端按返回/返回箭头退出播放页 | **投送立即结束**，接收端**干净退出播放页**（不出现播放器错误码）；发送端回到列表 |

| E1b | 发送端断网/被杀导致 HTTP 流中断 | 接收端显示「投送已结束」并自动收起播放页（不再显示 `播放器错误 what=…`） |

## 3. 已知不可自测项

- AirPlay 只有 Apple 设备能发起：**A1–A10 必须由用户用 iPhone/iPad 实测**；
  我们可以在接收端侧收集日志（设置 → 日志）用于排查。
- 平板 / Android TV / 折叠屏若无设备，标注为「未验证」，仅保证 Compose 响应式布局与 TV 资源已就绪。

## 4. 日志与排查

- 接收端：设置 → 日志（应用内查看），或 `bash` 里通过 DSHA 读取设备日志。
- 发送端：通知栏状态 + 应用内实时码率/帧率。
- LANCast 连接失败时先确认：同一 Wi-Fi、接收端「局域网接收」已开、端口一致、未被防火墙拦截。
